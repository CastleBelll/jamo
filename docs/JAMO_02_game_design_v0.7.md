# JAMO — 게임 기획 v0.7

2026-09-11 / 기준 원본 v0.6 / Steam PC, 한국어 우선, Godot 4 계열의 2D 고정 화면 / 1인 제작.

[세계관 v0.3](JAMO_01_story_world_v0.3.md)은 서사, [밸런스 v0.3](JAMO_03_balance_detail_v0.3.md)은 모든 전투·확률·콘텐츠 수치를 소유한다. 이 문서는 행동과 상태 전이를 소유한다. 과거 버전은 구현 기준이 아니다. 엔진의 구체 버전은 구현 시작 시 고정하고 프로젝트에 기록한다.

## G1. 게임의 약속과 완료 범위

자모를 정화하며 필요한 활자를 회수하고, 덱의 확률을 조정해 단어를 복원하고, 그 뜻으로 전투의 우선순위를 바꾸는 로그라이트다. 매 전투에서 “누구를 먼저 정화할까”, 보상에서 “어떤 글자를 넣거나 뺄까”, 복원에서 “확실한 성장과 목표 단어 중 무엇을 택할까”를 판단한다.

이번 제작 범위는 W1~20, 페이지 하나와 배경 상태 둘, B7의 기본 단어 22개와 합성 결과 2개, 중간보스 2종과 단어 보스 2종이다. W20 정화가 RUN 성공이며 결과 화면으로 간다. 실패는 안정도 소진, 포기는 메뉴에서 확인 후 귀환이다. 어느 경우든 다음 RUN은 W1에서 시작한다. 무한 Wave와 본편 결말은 후속 기획이다.

첫 재미 검증은 W1~5와 검·불·벽을 포함한 기본 단어 일부로 먼저 한다. 전체 Slice를 만든 뒤에야 클릭감과 복원 재미를 평가하지 않는다. 이번 문서 작업에서는 게임 코드나 기존 에셋을 변경하지 않는다.

## G2. 상태 전이와 초반 경험

```text
서고 → 시작 구성 선택 → WAVE_PREP → COMBAT
COMBAT → 안정도 소진 → RESULT → 서고
COMBAT → 스폰 종료 및 적·패턴 잔존 0 → CLEAR
CLEAR → 자모 정리 → FORGE → 빌드 확정 → 다음 WAVE_PREP
W20 CLEAR → RESULT → 서고
```

W20 뒤에는 자모 정리·Forge가 없다. CLEAR부터 전투 시계는 정지한다. 각 화면의 완료 버튼은 단 한 번만 전이를 실행한다. 자동 다음 Wave는 기본 꺼짐이며 이번 Slice에는 구현하지 않는다. 적의 도달 퇴장도 잔존 수에서 제외한다. 살아남은 채 모든 적을 놓쳐도 Wave는 종료되지만 회수·정화 Gold는 없다.

최초 RUN은 Starter A로 서고 메뉴 대신 짧은 오프닝 뒤 W1에 진입한다. 먼저 “자모를 눌러 마지막 문장을 지키세요”, 첫 회수 때 “이 글자로 단어를 만들 수 있습니다”만 안내한다. 최초 W1 보상은 추가/건너뛰기만 허용해 보장 손패의 재료가 교체로 사라지는 것을 막는다. 교체는 W2부터, 다음 RUN부터는 W1에도 허용한다. Forge의 추천 두 단어 중 하나를 골라 바로 W2에 효과를 확인하며 전체 후보도 펼칠 수 있다. 튜토리얼 손패는 B3의 실제 덱 토큰을 재배열한 손패로 만들며 가짜 자모를 지급하지 않는다. 이후에는 정상 추첨한다.

W2에서 목표 단어 핀과 Lock, W3에서 필요할 때 Rank, W5 뒤에 제거, W6에서 시너지, W10 이후 합성을 설명한다. 기능은 조건 충족 시 이미 사용할 수 있고 안내만 순차 노출한다. 설명을 닫아도 기능이 잠기지 않는다. 최초 목표는 “단어 하나의 힘을 써 보고 거대한 ㅁ에 도전하기”다. 첫 보스 격파를 의무로 만들지 않는다.

재도전은 모든 안내를 다시 보이지 않으며 시작 덱 선택과 목표 핀을 유지한다. 시작 덱은 연구로 다른 선택지를 해금하되 능력치가 상위인 덱으로 취급하지 않는다.

## G3. 전투와 입력 계약

플레이어 캐릭터 이동은 없다. 적 위에서 왼쪽 버튼을 누르면 정화 타격을 한다. 누르고 있기 역시 같은 전역 공격 간격으로 반복한다. 두 입력을 겹쳐 추가 공격할 수 없다. 커서가 적을 벗어나면 자동으로 다른 적을 추적하지 않는다. 빈 공간 입력은 공격 쿨다운을 소비하지 않고 빗클릭 통계에만 기록한다. 메뉴를 클릭한 입력이 전장으로 전파되어서는 안 된다.

겹친 클릭 후보는 커서와 중심 거리가 가장 가까운 적, 동률이면 먼저 생성된 ID로 한 개만 결정한다. 얇은 모음도 같은 크기의 원형 클릭 영역을 갖는다. 단어의 범위 효과는 별도 효과 판정으로 처리한다. 키보드 접근성 모드는 Tab으로 활성 대응물(남은 예고시간 순), 일반 적(도달 예상시간 순), 보스 순서로 순환하고 Space로 같은 공격을 실행한다. UI가 포커스를 가진 동안 전장 입력은 중지한다.

적 우선순위는 가까운 적, 빠른 적, 보호막을 주는 특수 적, 목표 자모 사이에서 생긴다. 목표 자모에는 작은 책갈피 테두리를 표시하며 드랍 확정으로 오해시키지 않는다. 자동 공격이 있더라도 위협 적과 보스 패턴은 직접 겨냥할 이유가 있어야 한다.

자모 모양과 전투 직업은 분리한다. B5의 모든 자모는 기본 NORMAL이며 특정 글자를 얻기 위해 항상 더 어려운 적을 잡아야 하는 구조를 피한다. W6부터 아래 변형이 붙는다. 생성 가중치와 변형 확률은 별도 추첨한다.

| 변형 | 눈으로 아는 특징 | 행동과 대응 |
|---|---|---|
| LIGHT | 앞쪽 작은 잔상과 화살표 | 빠르게 접근; 우선 정화 |
| HEAVY | 굵은 이중 외곽선 | 느리고 단단함; 지속 피해를 걸고 다른 적 처리 |
| GUARD | 끊어진 사각 테두리 | 같은 통로의 가장 앞선 다른 적에 피해 감소; 수호자를 먼저 정화 |

도달한 일반 적은 안정도 피해를 한 번 주고 퇴장한다. 정화 보상을 지급하지 않는다. 보스는 고정 위치에서 패턴으로 공격하며 접촉 이동을 하지 않는다. 보스 패턴 목표물은 자모 회수원이 아니고 Gold도 주지 않는다.

## G4. 덱·회수·추첨을 하나로 정의

덱은 고유 토큰 ID를 가진 자모의 다중집합이다. 같은 ㄱ 두 장은 서로 다른 토큰이다. 정화 시 같은 자모만 회수하며 전투 중 임시 보관함으로 자동 이동한다. B4의 상한 이후 판정은 중지한다. 피티 카운터는 Wave 시작 시 초기화한다. 연속 실패 뒤 확정 회수와 무작위 성공 모두 카운터를 초기화한다.

일반 Wave 보상에서는 허용 횟수만큼 `추가`, `교체`, `건너뛰기`를 고른다. 교체는 덱 한 토큰과 회수 한 토큰을 맞바꾼다. 중간보스·W10 뒤에는 추가 정리 행동 `제거`를 사용할 수 있다. 덱 최소·최대 크기를 UI와 모델 모두 검사한다. 정리하지 않을 자유가 있고 미선택 회수는 사라진다. 미선택 자모의 Gold 전환은 없다. 회수가 없어도 정리 가능 사건에서는 제거를 허용한다.

**Forge마다 전체 현재 덱을 새로 섞는다.** 이전 Wave의 Draw/Discard 순서를 이월하지 않는다. 해당 Forge 안에서는 비복원 추첨이다. 첫 손패를 Draw에서 뽑고, Reroll 때 잠그지 않은 토큰을 Discard에 보낸 뒤 빈칸만 Draw에서 뽑는다. Draw가 소진되면 Discard를 섞어 이어 뽑는다. 손패와 Lock 토큰은 재추첨 풀에 들어가지 않는다. 따라서 같은 글자가 돌아올 수는 있어도 같은 토큰이 손패에 중복될 수는 없다. Forge 종료 시 모든 토큰이 다시 덱에 포함된다. 토큰 수 보존은 필수 불변식이다.

이 변경으로 “지난 Forge에서 무엇을 버렸는지”를 외우기보다 덱 구성과 현재 Lock에 집중한다. 확률 분석도 이 규칙만 사용한다.

## G5. Forge·한글 판정·실패

UI는 허용된 단어 목록을 기준으로 현재 손패의 **자모 개수**가 각 요구 개수 이상인지 검사한다. 순서 맞추기·키보드 단어 입력·슬롯 드래그는 요구하지 않는다. 초성 ㅇ도 필요하고 받침 중복도 별도 필요하다. 활의 ㅘ는 ㅗ+ㅏ, 광기의 ㅘ도 같은 분해를 적용한다. ㅕ·ㅛ는 독립 토큰이다. 그 외 겹모음·쌍자음·겹받침은 현재 제작 목록에 없으며 암묵 지원하지 않는다. B7의 요구 자모가 실행 데이터의 정본이며 Unicode 분해 검사는 오타 검출용이다.

시작부터 해금된 단어는 미발견이어도 이름·재료·효과를 볼 수 있다. 사전 발견 여부와 제작 해금은 별개다. 목표 한 개를 핀하면 부족 자모와 덱 내 개수, 목표가 덱으로 가능한지 표시한다. 불가능한 목표는 “현재 덱에 ㅋ 없음”처럼 안내한다. 게임은 검증되지 않은 성공 확률을 임의 표시하지 않는다.

손패 클릭은 Lock 토글이다. 잠금 개수 제한을 넘기면 기존 잠금을 해제하지 않고 짧은 안내를 준다. Reroll은 남은 횟수와 바뀔 칸을 미리 보여준다. 생성 가능한 후보는 신규/Rank 상승/교체 필요 여부로 분류하고 효과 비교를 제공한다. 확률 보너스로 리롤을 무료 반복하는 시스템은 없다.

복원은 Forge당 한 번. 후보 선택 → 장착 또는 교체 확인 → 단어/Rank 반영 → 사전·복원도 반영을 하나의 거래로 처리한다. 취소하면 손패와 횟수는 그대로다. 이미 최대 Rank인 보유 단어는 후보에서 제외한다. 슬롯 때문에 교체가 필요해도 유효 후보다. 교체로 사라진 단어를 다시 만들면 Rank 1부터다. 버린 단어의 Rank를 숨겨 저장하지 않는다.

마지막 Reroll 뒤에도 **신규 장착·Rank 상승 가능한 후보가 전혀 없으면** 복원 실패로 판정한다. 후보가 있는데 건너뛰면 자발적 포기이며 피티가 늘지 않는다. 실패 시 이번에는 B3의 안정도 회복, 다음 Forge에는 추가 Reroll을 받는다. 복원 성공 시 실패 보정은 초기화한다. 보정도 안 쓰고 다음 Wave로 넘어갈 수 있다. 진행이 막히거나 무한 재추첨되지 않는다.

## G6. 단어·시너지·합성의 수명

장비·유물·특수효과·위험은 효과 설명 분류로 유지한다. 실제 보유 공간은 **공용 빌드 슬롯**이고 위험 단어만 추가 상한을 갖는다. 종류별 빈칸이 남았는데 단어를 버리는 혼란을 줄인다. 보유한 단어 ID는 중복될 수 없고 재복원은 Rank 상승이다. 모든 Rank 수치는 B7에서 명시하며 일반 배율을 덧씌우지 않는다.

시너지는 활성 보유 단어의 태그를 서로 다른 ID 단위로 센다. Rank는 태그 수를 늘리지 않는다. 봉인된 단어는 집계에서 빠지고 해제 때 다시 들어온다. 임계치 효과는 가장 높은 단계만 적용한다. 이번에는 B8의 세 시너지만 구현한다.

합성은 Forge 복원 후 빌드 확정 화면에서 선택하는 별도 행동이다. 해당 재료 두 단어가 활성 보유 중이고 B8 조건을 충족하면 미리보기를 연다. 두 재료와 효과를 제거하고 합성 결과 Rank 1 하나를 넣는다. 결과를 이미 보유하면 합성 불가. 이번 빌드 확정에서 한 번만 합성하며 취소는 무료다. 합성은 Forge의 추가 단어 복원을 허용하지 않는다. 재료를 다시 확보해야 반복 합성이 가능하고 결과 Rank를 높이는 용도로 쓰지 않는다. 결과 단어는 직접 Forge 후보가 아니며 Rank 최대 1이다.

공존형 조합은 별도 ‘합성어’ 항목을 중복 생성하지 않고 시너지로 통합한다. 합성으로 태그 수가 줄어 시너지가 꺼질 수 있으며 미리보기에서 명시한다. 영구 합성 발견은 레시피 열람 기록이며 다음 RUN 자동 지급이 아니다.

## G7. 피해와 효과 처리 계약

피해 수식·상태 지속시간은 B1/B7을 따른다. 직접 타격, 자동 타격, 파생 타격, 상태 피해는 서로 다른 source를 갖는다. ‘수동 적중’ 효과는 클릭/누르고 있기/접근성 입력으로 적에게 실제 피해를 준 경우만 발동한다. 파생·상태 피해가 다시 수동 적중 효과를 발생시키지 않는다. 확률 치명은 직접 타격만 적용한다. 광기의 빠른 입력도 같은 계약이다.

한 전투 틱은 입력 판정 → 직접 피해 → 적중 상태 부여(생존 대상만) → 예약된 자동/상태 피해 → 정화 처리 → 보스 패턴/도달 피해 → 패배 → 클리어 순서다. 동일 단계는 entity_id 순서로 처리한다. 정화와 보상은 개체당 한 번만 실행한다. 이미 정화된 적의 패턴·접촉은 취소한다. 보스 정화 시 잔여 부하와 예약 패턴을 먼저 제거하므로 그 틱에 해당 부하가 줄 도달 피해도 취소된다. 일반 Wave에서 도달 피해가 안정도를 소진시키면 적이 모두 퇴장했더라도 패배를 우선한다.

대상 선택의 공통 ‘가까운 적’은 월드 거리, 동률은 entity_id다. ‘앞선 적’은 마지막 문장까지 남은 경로 길이가 작은 적이다. 범위 내 대상이 없으면 효과를 버리고 저장하지 않는다. 공격 카운터는 Wave마다 0, 주기 타이머도 새로 시작한다. 재장착으로 쿨다운을 즉시 발동시키지 않는다.

자동 공격의 앞선 적 선택에서는 부하를 보스보다 우선하고 부하가 없으면 보스를 선택한다. 보스의 논리 통로는 중앙이며 ‘남은 경로 25% 이하’ 조건은 충족하지 않는다. 대응물은 적 대상 목록에서 제외한다. 보스도 거리 기반 범위 피해를 받을 수 있다. 대상 수보다 적이 적으면 존재하는 적만 한 번씩 맞힌다. 보스에 적용할 때 별도 언급 없는 상태/피해는 일반 적과 같다.

## G8. 보스: 예고 → 대응 → 결과

보스는 고정 상단 위치에 등장하고 일반 Wave의 무작위 적 스폰을 사용하지 않는다. 수치표에 지정된 유한 부하만 별도 생성한다. 보스 패턴의 봉인/보호막/표식은 이름과 남은 시간을 표시한다. 공통 기본 클릭만으로 모든 대응물을 처리할 수 있다. 특정 상태이상 면역을 요구하지 않는다.

| 보스 | 반복 패턴 | 직접 대응 | 실패 결과 / 후반 변화 |
|---|---|---|---|
| W5 거대한 ㅁ | 문장 앞 착지 원 예고 | 보스 옆 교정점 타격 | 안정도 피해; 후반 예고 단축 |
| W10 침묵 | 비위험 활성 단어 하나에 봉인선 연결 | 별도 끊기 표식 타격 | 해당 단어 잠시 봉인; 후반 주기 단축 |
| W15 질주 ㅇ | 세 통로 중 다음 돌진 통로 예고 | 해당 통로의 정지 표식 타격 | 안정도 피해; 후반 표식 요구 타격 증가 |
| W20 탐욕 | 활자 고리 충전, 부하 정화 때 보호막 축적 | 고리 표식을 끊어 보호막 제거·충전 방지 | 안정도 피해; 후반 주기 단축 |

대응물은 모든 공격으로 피해를 받는 적이 아니라 **수동 입력 횟수**를 받는 공통 PatternTarget이다. 공격 피해·치명·자동 공격이 대응 횟수를 바꾸지 않는다. 대응 중 보스를 때려도 피해는 정상 적용되어 딜과 안전을 선택할 수 있다. 봉인은 위험 단어를 대상으로 잡지 않아 페널티만 사라지는 악용을 방지한다. 봉인된 단어의 기존 상태는 만료까지 남고 새 발동·유지형 수치·시너지 태그만 중지한다. 해제 후 타이머는 새 주기부터 시작한다.

침묵이 봉인할 단어가 없으면 해당 실패 결과를 안정도 피해로 대체한다. 봉인 가능한 단어가 둘 이상일 때만 연속 동일 대상 금지. 탐욕의 보호막은 Gold 획득액이 아닌 지정 부하 정화 사건 수로 증가하므로 경제 빌드에 비례한 벌을 주지 않는다. 영구 Gold를 차감하지 않는다.

## G9. 진행·메타·결과

W1~4는 첫 효과와 Rank, W5는 첫 정리, W6~9는 변형 적과 시너지, W10은 빌드가 잠시 끊기는 대응, W11~14는 합성 대안, W15는 통로 대응, W16~19는 혼합 압박, W20은 수입과 패턴 대응의 교차다. 새 시스템은 이 범위를 넘겨 추가하지 않는다.

영구 성장에는 안정도 소폭 증가와 시작 덱 선택만 제공한다. 기본 공격·공격 속도·Forge 손패 크기·Lock·Reroll의 영구 증가를 이번 범위에서 제거한다. 기본적인 재료·효과·시너지 설명은 무료다. 복원도는 이름표와 서고 기록을 성장시키며 전투 보너스를 주지 않는다. 구체 보상은 B10.

결과에는 종료 이유, 도달/클리어 Wave를 구분한 기록, 안정도 피해 원인 상위 항목, 대표 빌드, 신규 발견, 실제 획득 Gold, 가능한 다음 목표를 표시한다. 추천은 해금된 합성 또는 핀한 단어에 부족했던 자모에서 한 개만 선택한다. “연구를 사야 승리 가능”이라는 고정 문구는 없다.

## G10. 화면과 조작 명세

전투 좌표·간격·폰트 최소 크기는 B11에 정의한다. 화면 비율이 달라져도 전장 좌표는 고정된 논리 화면을 유지하고 여백으로 처리한다. 커서는 동일한 좌표 변환을 사용한다. UI는 Anchor/Container 기반이며 텍스트 확대 때 줄바꿈하고 전장을 덮는 상세 패널은 일시정지 화면에서만 연다.

| 화면 | 항상 표시 / 주 행동 | 상세 표시 / 전환과 피드백 |
|---|---|---|
| 마지막 서고 | Gold, 발견 수, 최고 기록, RUN/연구/사전/설정 | 사건 기록은 선택 열람; RUN 클릭 시 구성으로 |
| RUN 시작 | 시작 덱 목록·총 장수, 목표 핀, 시작 | 덱별 자모 수·제작 가능 단어; 확정 후 준비 |
| HUD | Wave, 안정도 현재/최대, 남은 적, 이번 RUN Gold, 빌드 아이콘, 임시 회수 수 | Esc/빌드 클릭 시 정지; 적 Hover는 HP·변형 |
| Wave Clear | 정화/놓침, 안정도 손실, 회수 수 | 짧은 연출 후 자모 정리와 같은 패널로 연결 |

| 보스 등장 | 이름, 이번 대응 한 줄, 건너뛰기 | 최초 짧은 소개; 전투 시작 전만 표시 |
| RUN Result | 종료 사유, Gold, 신규 기록, 대표 단어, 재도전/서고 | 원인 상세와 사전 항목 이동; 중복 정산 금지 |

Esc는 가장 위 팝업부터 닫고 최상위에서 정지 메뉴를 연다. Enter는 포커스 버튼만 실행하고 기본적으로 파괴적 선택에 포커스하지 않는다. 회수/복원/교체 버튼은 글자와 아이콘을 함께 사용한다. Tooltip은 마우스와 키보드 포커스 양쪽에서 열리고 중요한 위험 페널티는 Tooltip 안에만 숨기지 않는다. 포커스 상실·최소화는 자동 정지한다.

## G11. 2D 전장·움직임·제작 자산

문장 행은 배경 안내선, 실제 이동은 통로별 Path2D다. 각 통로에 두 평행 하위 경로를 두고 빈 경로부터 배치한다. 같은 경로에서 뒤의 적은 앞의 적과 최소 간격을 유지하도록 진행량을 제한한다. 스폰 위치가 막히면 해당 생성만 보류하고 한 번에 몰아서 생성하지 않는다. 자유 이동과 물리 회피를 함께 구현하지 않는다. 경로는 마지막 문장의 서로 다른 도달점에서 끝나므로 중앙에 적이 뭉치지 않는다. 접촉 판정은 경로 종료다.

시각 흔들림은 Monster/VisualPivot 아래에만 적용하며 루트 경로·클릭 영역을 움직이지 않는다. 보스는 B11의 고정 구역을 사용하고 부하의 경로를 가리지 않는다. 배경은 밝은 원고/외곽 먹 번짐 두 상태만 만든다. 보스는 동일 페이지에 교정선·고리 Overlay를 얹는다. 지형 피해·미로·가려지는 행은 없다.

| 프로필 | 자모 | VisualPivot 동작 |
|---|---|---|
| ROLL | ㅇ | 회전 ±8°, 주기 0.6초; 윤곽을 알아볼 수 있는 범위 |
| BOUNCE | ㅁ, ㅂ | 위로 6px, 0.55초; 착지 scale (1.06,0.92)→(1,1) 0.1초 |
| LIGHT_STEP | ㅅ, ㅈ, ㅊ | 좌우 회전 ±5°, 0.3초; 위로 3px |
| HEAVY_STEP | ㄱ, ㄷ, ㅋ, ㅍ | 회전 ±3°, 0.7초; 착지 그림자 1.08→1 |
| SWAY | ㄴ, ㄹ, ㅎ | 회전 ±4°, 0.8초; 획 자체의 과도한 변형 없음 |
| GLIDE | ㅏ, ㅓ, ㅗ, ㅜ, ㅣ, ㅕ, ㅛ | 세로 2px, 1초; 읽히는 방향 고정 |

기본 자모는 정지 Sprite 한 장과 공통 피격/정화 셰이더로 충분하다. 눈·표정은 필수 자산이 아니다. 모션은 공유 Resource, 정화/피격은 공통 AnimationPlayer로 만든다. 움직임 줄이기 옵션에서 변위를 0으로 해도 클릭 정보가 같다.

최소 자산 목록: B5의 자모 글리프 20종, 종이 배경 1장, 외곽 먹 Overlay 1장, 서고 배경과 상태 레이어, 보스 글자 조합 4종, 공통 표식 1종, 상태 아이콘 3종, 단어 텍스트 카드와 분류 아이콘 4종, 버튼/패널 Theme. 단어별 별도 일러스트를 24장 요구하지 않는다. 그림은 사람이 또는 AI로 제작할 수 있지만 실제 한글은 검수된 폰트/글리프로 올린다. AI 이미지 안의 한글을 그대로 데이터로 쓰지 않는다. 폰트·음원 출처와 배포 허용 라이선스는 자산 반입 시 기록한다.

## G13. Godot 제작 계약

구조는 .tscn, 튜닝 데이터는 .tres, 동작은 .gd, 시간 연출은 AnimationPlayer, UI는 Theme Resource로 분리한다. 에디터에서 페이지 경로·단어 수치·Wave·보스를 수정할 수 있어야 한다. UI 전체를 코드에서 생성하거나 옛 게임을 복원하는 작업을 기본 Phase로 넣지 않는다.

```text
scenes/ : hub/last_library, run/run_game, run/corrupted_page,
          monsters/jamo_monster, bosses/boss_base, effects/pattern_target,
          ui/hud, ui/reward_forge, ui/build_panel, ui/result, ui/codex, ui/settings
resources/ : balance, words, waves, bosses, decks, motion_profiles, synergies,
             compounds, research, narrative
scripts/ : combat, deck, forge, progression, persistence, ui
```

`corrupted_page.tscn`: Node2D → Paper(Sprite2D), Overlays(Node2D), Paths(Path2D×6), Enemies(Node2D), BossAnchor(Marker2D), LastSentence(Node2D), Effects(Node2D). HUD는 별도 CanvasLayer/Control이다.

`jamo_monster.tscn`: Node2D → VisualPivot(Node2D)/Sprite2D, Shadow(Sprite2D), ClickArea(Area2D)/CollisionShape2D, StatusAnchor(Marker2D), AnimationPlayer. 그림·클릭·이동 책임을 분리한다. 트랜스폼에 여러 Tween을 동시에 걸지 않고 이동 모션과 피격 모션을 서로 다른 노드에 적용한다.

## G14. 저장·중단·복구

Meta: save_version, Gold, 연구, 사전·복원도, 보스 기록, 최고 도달/클리어 Wave, 사건 기록, 설정. Run: run_id, phase, Wave, 안정도, 덱 토큰, 손패/Draw/Discard, Lock/Reroll, 빌드/Rank, 임시 회수, 실패 보정, RNG 상태, 획득 누적, 정산된 event_id. Content version도 함께 기록한다.

전투 시작 직전에 체크포인트를 저장한다. 전투 도중 정상 종료·강제 종료는 다음 실행에서 그 Wave 시작 상태로 재개한다. 해당 Wave의 미정산 Gold/기록은 체크포인트로 함께 되돌린다. UI에 “전투 중 종료하면 현재 Wave부터 다시 시작합니다”를 표시한다. 실시간 적 상태 저장은 Slice에 요구하지 않는다.

Wave Clear, Forge의 Reroll/Lock/복원/합성, 보상 선택을 확정할 때 전체 논리 상태를 원자적으로 저장한다. 따라서 Forge 재접속은 같은 손패·횟수·RNG로 돌아온다. 실패/포기/완주 때 현재 Wave까지의 수입과 기록을 정산하고 Run을 종료하는 거래를 함께 저장한다. 이전 Clear에서 지급한 Gold를 다시 더하지 않는다. result_id가 같으면 결과 재열람 시 추가 지급하지 않는다.

단일 프로필 스냅샷을 임시 파일에 쓴 뒤 검증·교체하고 이전 정상본을 백업한다. 손상 시 백업 복구와 안내, 둘 다 실패하면 사용자 동의 후 새 프로필을 만든다. 자동으로 기록을 조용히 지우지 않는다. 이전 기획의 저장은 호환을 보장하지 않으며 원본을 보존하고 신규 프로필 선택을 안내한다. 실제 마이그레이션은 출시된 저장 형식이 생긴 뒤 버전별로 명시한다.

## G15. 구현 순서와 인수 조건

| 단계 | 결과물 | 다음 단계 진입 조건 |
|---|---|---|
| P0 | 데이터 스키마·화면 골격·W1 적과 입력 | 좌표·겹침·정화/도달 중복 검사 통과 |
| P1 | W1~5 + 회수/덱/Forge + 검·불·벽 등 기본 풀 | 첫 효과가 W2 행동을 바꾸고 B12 첫 경험 기준 충족 |
| P2 | 22 기본 단어·Rank·위험·상태·시너지·합성 | B7 전 항목 데이터 검증, 파생 효과 무한 재귀 없음 |
| P3 | W1~20과 보스 4종 | 기본 입력으로 모든 패턴 대응, 시간·실패 원인 기록 |
| P4 | 서고·연구·사전·서사·저장·복구 | 종료/재개/중복 정산 통합 검사 통과 |
| P5 | 실제 아트·음향·접근성·밸런스 | B12의 사용자 테스트와 성능 측정 완료 |

피격·회수·복원 피드백은 P1부터 최소 버전이 있어야 한다. P5는 완성도를 높이는 단계이지 손맛을 처음 추가하는 단계가 아니다. 인수 검사는 토큰 보존, Unicode 요구 자모, 잠금 재추첨, 최대 Rank 제외, 슬롯 교체 취소, 합성 태그 재계산, 봉인 해제, 정화/접촉 동시 사건, 저장 거래 재실행을 포함한다. 각 경계는 모델과 실제 화면을 연결한 통합 검사로 확인한다.

확률 계산이 통과해도 재미가 검증된 것은 아니다. B12의 실측이 기준을 벗어나면 단어·맵을 늘리지 말고 해당 루프를 수정한다. NPC, 장비 강화, 농사, 온라인, 오프라인 진행, 복잡한 지형, 대량 단어 추가는 이번 범위에 없다.
