## 1. 총평

기존 초안에는 핵심 소재와 큰 흐름이 있다. 그러나 단어 데이터가 닫힌 목록으로 정의되지 않았고, 자모 공급과 단어 제작 확률이 검증되지 않아 플레이 중 어떤 선택이 가능한지 알 수 없었다. 여기에 큰 영구 공격력 증가, 많은 분류 슬롯, 여러 보정·해금 체계가 겹쳐 ‘단어를 만들어 전투가 바뀐다’는 중심이 흐려질 위험이 있었다.

이번 개정은 제작 가능한 규칙·데이터·실패 처리까지 확정했다. 다만 기획과 확률 계산으로 실제 재미를 증명할 수는 없다. P1의 짧은 실제 플레이와 B12의 사용자 관찰을 다음 검증으로 남긴다. 재미 검증 전 전체 아트·콘텐츠 제작에 들어가지 않는다.

## 4. 범위 결정과 의도적인 절충

- 공용 슬롯과 강한 Lock은 유효한 단어를 만들기 쉽게 한다. 대신 최대 Rank 반복 후보 제외, 긴 단어 중복 자모, 다른 태그와 합성을 통해 선택을 남긴다. 특정 단어 목표 성공률이 너무 높아지면 덱 구성·Lock부터 재검토한다.
- 위험 단어가 없는 새 프로필은 19개 단어만 사용한다. W5 정화 후 다음 RUN부터 나머지 3개와 관련 자모가 추가된다. 초기 확률과 전체 해금 확률을 혼동하지 않는다.
- 합성 두 개는 품질을 확인할 최소 제작 범위다. 개수가 작다는 이유로 이전 초안의 ‘5개 이상’을 함께 요구하지 않는다.
- 복원도 전투 보너스와 다수 연구 제거로 메타 보상 밀도는 낮아진다. 그 자리를 사전·서고·시작 덱 선택이 실제로 채우는지 관찰한다. 재미가 약하면 먼저 RUN 선택을 고치며 큰 영구 공격 보너스로 덮지 않는다.

## 5. 검증 기록

완료: 최신 원본 세 문서 전체 읽기, 새 문서 작성, 단어 자모 Unicode 분해 대조, 시작 덱 구성·미사용 자모 검사, 첫 손패 전수 조합 계산, Reroll 모의실험, Drop 피티 기대값 계산. 상세 수치와 재현 조건은 확률 보고서 참조.

최종 검토는 게임성·세계관·UX·확률/경제·저장/구현의 관점으로 직접 교차 검토했다. 튜토리얼 직전 교체로 보장 재료가 없어지는 경우, 보스 정화와 부하 접촉의 동시 처리, 상태 틱의 재적용 초기화, 자동 공격의 보스 우선순위, 대응물과 보스 클릭 영역 겹침을 수정했다. 자동 문서 검증은 기본 단어 22개·합성 2개·일반 Wave 16개·빈도 행 20개·문서 링크 14개를 검사해 통과했다.

사용자 지침의 `$code-review`는 현재 제공 목록과 설치된 skill 경로에서 찾을 수 없어 해당 스킬을 실행했다고 주장하지 않는다. 별도 에이전트 리뷰는 실행하지 않았다.

미실행: Godot 게임 구현·엔진 테스트·플레이테스트·프레임 성능·실제 사용자 재미 검증. 이번 요청이 기획 완성 단계이므로 게임 코드는 구현하지 않았다. 계산 통과를 플레이테스트 통과로 바꾸어 보고하지 않는다.

## 6. Fable에게 전달할 시작 지시

“위 최신 세 문서만 현재 설계로 사용하고 P0→P1부터 구현한다. 데이터는 .tres, 화면/구조는 .tscn, 연출은 AnimationPlayer, UI는 Theme로 구성한다. 기존 구현이나 DEPRECATED 규칙을 복원하지 않는다. P1에서 첫 복원과 전투의 차이를 확인한 뒤 다음 단계로 간다. 모든 미실측 기준은 B12에 따라 검증하고 실패하면 확장보다 현재 루프를 먼저 수정한다.”
