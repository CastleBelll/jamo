# JAMO 기획 확률 검증 보고서

실행일 2026-09-11. 정본은 [밸런스 v0.3](../JAMO_03_balance_detail_v0.3.md) B3~B7. 실행: `python docs/analysis/verify_planning.py`. Python 표준 라이브러리만 사용하며 게임 코드는 구현하지 않는다.

## 1. 검증 범위와 방법

기본 22개 단어의 자모 요구를 Unicode 한글 음절 분해와 비교했다. ㅘ만 ㅗ+ㅏ로 분리하고 초성 ㅇ 및 받침의 개수를 포함했다. 합성 결과 2개는 직접 추첨 단어에서 제외한다. 전체 필요 토큰 빈도 74, 사용 자모 20종, 평활 가중치 합 114다. 새 프로필의 19개 단어는 빈도 57, 자모 17종, 가중치 합 91이다. 상세 빈도 정본은 B6 표다.

시작 덱은 토큰 인덱스를 구분한다. 20장 중 6장 손패 38,760개, 7장 손패 77,520개를 전수 조사했다. 중복 자모가 있으므로 글자 문자열만 중복 제거하지 않는다. 각 토큰 조합은 같은 확률이다. 후보 수는 해금된 서로 다른 단어 ID 개수다.

Reroll 실험은 독립 Forge 20,000회씩, seed=20260911, Python `random.Random` 사용. 정책·덱·설정마다 seed를 다시 초기화한다. 실패 피티·튜토리얼 손패·덱 변경·현재 보유 단어는 적용하지 않는다. 초기 19개만 사용하므로 위험 단어의 조건부 활성 여부와 위험 슬롯은 결과에 영향을 주지 않는다.

‘아무 단어’ 정책은 후보가 하나라도 생기면 멈춘다. 후보가 없을 때는 현재 덱으로 가능한 단어 중 부족 토큰 개수가 가장 적은 것을 고르고, 동률이면 보유 재료 개수 내림차순, 단어 문자열 순으로 정한다. 손패 순서대로 목표에 필요한 자모를 Lock 상한까지 잠근다. 항상 최적의 잠금이 되는 정책은 아니다.

‘불 목표’ 정책은 다른 단어가 가능해도 불을 만들 때까지 리롤한다. 두 정책은 목적이 다르므로 결과를 하나의 평균으로 합치지 않는다. Discard 순환은 G4 계약과 같다. 같은 글자가 리롤 뒤 다시 나와도 같은 토큰이 손패에 중복되는 것은 아니다.

## 2. 최종 시작 덱 결과

| 덱 / 설정 | 첫 손패 제작 불가 (전수) | 첫 평균 후보 (전수) | 아무 단어 정책 최종 실패 (모의) | 종료 시 평균 후보 (모의) |
|---|---:|---:|---:|---:|
| A / 6칸·Lock2 | 48.7874% | 0.72030 | 4.430% | 1.40415 |
| A / 7칸·Lock3 | 31.7466% | 1.15818 | 0.725% | 1.76000 |
| B / 6칸·Lock2 | 50.7663% | 0.66164 | 5.005% | 1.32570 |
| B / 7칸·Lock3 | 33.7190% | 1.07032 | 0.965% | 1.67480 |

7칸 설정의 최종 성공률 근사 95% 신뢰구간은 A 99.275% ±0.118%p, B 99.035% ±0.135%p이다. 이 구간은 독립 샘플의 이항 표준오차에 대한 정규 근사이며 실제 사람의 정책 차이나 모델 오차를 포함하지 않는다. 첫 손패 전수 결과에는 표본 오차가 없다.

| 덱 | 첫 손패 불 제작 가능 (전수, 7칸) | 불 목표 리롤 후 성공 (모의) | 근사 95% 오차 폭 |
|---|---:|---:|---:|
| A | 9.52657% | 88.530% | ±0.442%p |
| B | 5.41796% | 83.395% | ±0.516%p |

A는 ㄹ이 두 장이므로 불을 만들기 쉽다. B는 ㄴ·ㅁ을 늘린 대안이며 눈·물 방향으로 접근한다. A는 초기 덱에서 칼/눈 불가, B는 창 불가임을 검증했다. 필요 글자를 회수·교체해야 가능해진다. 덱이 단어 선택을 바꾸는 실제 구조적 차이다.

채택: 7칸·Lock3·리롤2. 6칸보다 첫 행동 불가를 줄이고 평균 최종 후보를 늘린다. 다만 불 목표 성공률이 높으므로 ‘모든 목표가 쉽게 반복되는가’라는 위험은 남는다. 후반 Rank3 제외와 목표 전환까지 검증해야 한다. 단어별 성공률을 전부 계산한 결과로 오해하지 않는다.

## 3. Drop 피티의 정확한 계산

상태 `(연속 미회수 수, 회수 수)`의 확률 질량을 정화 한 번씩 전이시켰다. 기본 25%, 연속 실패 4 뒤 다음 확정, 회수 6에서 중지. 운·보스 본체 보장 회수는 제외한다.

| 실제 정화 횟수 | 기대 회수 수 | 회수 0 확률 |
|---|---:|---:|
| 8 | 2.414886 | 0% |
| 10 | 3.086297 | 0% |
| 14 | 4.315801 | 0% |
| 20 | 5.632674 | 0% |
| 24 | 5.939066 | 0% |

5회 이상 정화하면 적어도 한 번은 회수하므로 표의 0%는 오류가 아니다. 실제 게임에서 적을 4회 이하 정화하고 Wave가 끝나면 후보가 없을 수 있다. ‘스폰된 적 수’ 대신 ‘실제로 정화한 적 수’로 해석해야 한다.

전체 해금 후 ㅍ의 스폰 확률은 3/114. 핀과 변형에 따른 선택적 정화가 없고 생성 자모와 회수 성공이 독립이면, 20정화의 기대 ㅍ 회수는 0.148228개다. 이 값은 적어도 한 번 얻을 확률이 아니라 **개수의 기댓값**이다. 목표 글자를 우선 정화하는 실제 플레이는 다른 분포를 가지므로 별도 측정한다.

## 4. 아직 검증하지 않은 것

- 보유 단어·Rank3·폭주 선행 조건을 포함한 후반 후보 분포.
- 최대/최소 덱, 새 글자 추가·압축 이후 확률, 모든 긴 단어의 목표 성공률.
- 실제 정화 우선순위·핀 보정·운·부하 스케줄이 결합된 전체 RUN 공급.
- 전투 DPS, 보스 승률, 사용자 피로, 재미, 실제 소요시간.

위 항목은 B12의 구현 후 검증 계획이다. 본 보고서는 수치 근거 없는 초기값을 줄이는 용도이며 제작 완료나 재미 인증이 아니다.

## 5. 초기 계산에서 수정한 항목

최초 계산용 덱에는 이전 초안에서 가져온 ㅡ가 남았지만 최종 22개 단어에 사용처가 없었다. A는 ㅊ, B는 ㅋ으로 교체해 죽은 토큰을 제거하고 창/칼의 시작 방향을 나눴다. 초기 계산 결과는 최종 표에 섞지 않았다. 새 프로필의 위험 단어 미해금 조건도 최종 계산에 반영했다.
