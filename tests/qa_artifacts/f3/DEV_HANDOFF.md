## 3) 주의 / 보류 사항

### 스펙과 다르게 처리한 부분

1. **복합 모음 / 쌍자음을 기본 자모로 분해했다.**
   v0.3 §6.7 은 "단어 제작 데이터에서는 복합 모음을 하나의 구성 단위로 처리할 수 있지만
   필드 몬스터용 자모는 기본 자음/모음 우선" 이라고 한다. 자모 후보 카드는 단어의
   `required_jamo` 를 그대로 노출하므로, 기존 불/힘/돈/밥이 전부 기본 자모만 쓰는 것에 맞춰
   신규 단어도 전부 분해했다.
   - 화염: `ㅘ` -> `ㅗ` + `ㅏ`
   - 불꽃: `ㄲ` -> `ㄱ` + `ㄱ`
   - 체력: `ㅔ` -> `ㅓ` + `ㅣ`
   결과적으로 화염 6자모, 불꽃 7자모, 체력 6자모로 제작 비용이 tier-1(3자모)보다 무겁다.
   Day 당 자모 1개이므로 불꽃 완성까지 최소 7일이 더 걸린다. **밸런스 판단이 필요하면
   총지휘자 결정 사항이다.** 복합 모음을 한 단위로 쓰는 쪽으로 뒤집으려면
   `.tres` 의 `required_jamo` 만 고치면 되고 코드 변경은 필요 없다.

2. **불꽃 전이 반경을 px 가 아니라 m 로 넣었다.**
   문서는 `80px` 이라고 쓰지만 프로젝트는 3D 이고 아레나 카메라가 orthographic `size = 9.6`,
   뷰포트 세로 720px 이므로 `1m = 75px` 이다. 80px = **1.07m** 로 환산해
   `bulkkot.tres` 의 `radius` 에 넣었다. 실제 플레이에서 좁다고 느껴지면 Inspector 에서
   `Radius` 만 올리면 된다(코드 수정 불필요).

3. **`max_chain_depth` 라는 필드를 v0.3 §22.4 목록에 없지만 추가했다.**
   "무한 연쇄 방지 안전장치" 요구와 "수치 하드코딩 금지" 요구를 동시에 만족시키려면
   연쇄 한도가 데이터여야 한다. 불꽃은 `1` (전이된 화상은 재전이 불가, word_tree §3 스펙 그대로),
   후속 단어 `산불`(최대 3연쇄)이 이 값을 3으로 올리는 식으로 확장된다.

4. **`운` 의 tier 를 2 로 두었다.** 선행이 없어 Day 1부터 제작 가능하지만,
   §33 의 "최초 10개" 중 tier-1 4개와 구분하기 위해 tier-2로 표기했다. 게임 로직은 `tier` 를
   읽지 않으므로 동작에는 영향이 없다.

5. **`금` 은 해금 플래그만 노출한다.** 출현 확률 2%, 보상 ×5 는 F4 범위라 넣지 않았다.
   `GameState.is_golden_monster_unlocked()` 만 있고 확률 값은 아직 데이터로 존재하지 않는다.

6. **`운` 은 배율만 노출한다.** `GameState.get_special_spawn_multiplier()` 가 `1.05` 를 돌려주지만
   현재 이걸 읽는 코드가 없다. F4 특수 몬스터 스폰에서 곱해 써야 한다.
   운 미해금 시 `1.0` 이므로 F4 쪽에서 분기할 필요는 없다.

### 하위 호환 위험

7. **`EffectType` 은 끝에만 추가했다.** 기존 0~3 값이 그대로라 `bul/him/don/bap.tres` 는 안 건드렸다.
   신규 값은 4~8. 앞으로도 중간 삽입 금지.

8. **기존 세이브 파일은 그대로 열린다.** 저장 포맷을 바꾸지 않았고 `unlocked_words` 에
   해금 단어 id 만 들어가므로, 신규 단어를 모르는 옛 세이브도 정상 로드된다.
   반대로 신규 단어를 해금한 세이브를 옛 빌드에서 열면 `find_word()` 가 null 을 돌려주고
   그 단어 효과만 조용히 빠진다(크래시는 없음).

9. **`JamoMonster.apply_status_effect()` 시그니처가 인자 1개 늘었다.** 기본값 `chain_depth = 0` 이라
   기존 호출부(`click_controller.gd`)는 수정 없이 동작한다.

10. **`get_burn_effect()` 가 이제 `.tres` 원본이 아니라 사본을 돌려줄 수 있다.**
    화염 해금 시 `duplicate()` 한 사본에 보너스를 더한다. 원본을 직접 수정하면 재계산마다
    값이 누적되어 화상 피해가 무한히 커지므로 이 구조가 필요하다. 테스트로 고정해 두었다
    (`_test_hwayeom_raises_burn_tick`). 반환값을 캐싱해서 들고 있는 코드를 나중에 추가하면
    안 된다 — 단어 해금 시 인스턴스가 교체된다.
