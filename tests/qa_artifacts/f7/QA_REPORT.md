# F7 QA 보고서 — 메인화면 / 타이틀 (S1~S6)

- 판정: **FAIL**
- 검증일: 2026-09-10
- 엔진: Godot 4.7-stable (official), Vulkan Forward+, Intel UHD 770
- 검증 수단: ziva-godot MCP 라이브 실행(`run_scene`, 총 17회) + 에디터(`open_scene` /
  `get_scene_tree` / `get_screenshot`) + 헤드리스 보조
- 세이브 경로: `%APPDATA%\Godot\app_userdata\JAMO\jamo_save.json`

`start_godot` 툴은 이 ziva-godot 빌드에 존재하지 않는다. 대신 이미 붙어 있는 Godot
에디터 세션에 `run_scene` 으로 실제 게임을 임베드 실행해 화면을 보고 직접 조작했다.
헤드리스만으로 판정하지 않았다.

## 1. 결함 목록

### HIGH-1 — 타이틀 설정 패널이 포커스를 가두지 않는다 (S4 / S6 위반)

**재현**

1. 세이브 없는 상태로 타이틀 실행.
2. 키보드만 사용: `ui_down` x2 → 설정, `ui_accept` → 설정 패널 열림 (포커스 = 닫기).
3. `ui_up` 을 반복해서 누른다.

**기대**: 포커스가 패널 안(전체 화면, 마스터/음악/효과음 슬라이더, 닫기)에서만 순환한다.
DEV 검수 절차 6번("효과음 슬라이더를 화살표 키로 왼쪽 끝 근처까지 내린다")이 가능해야 한다.

**실제**: 포커스가 패널 밖, 패널에 가려진 타이틀 버튼으로 새어 나간다. 실측 이동 경로:

```
focus after open: SettingsCloseButton
  up from SettingsCloseButton -> ContinueButton   <- 패널 뒤 타이틀 버튼
  up from ContinueButton      -> BgmSlider
  up from BgmSlider           -> NewGameButton    <- 패널 뒤 타이틀 버튼
  up from NewGameButton       -> FullscreenCheck
  up from FullscreenCheck     -> <none>
```

- `%SfxSlider` 는 키보드로 **도달 자체가 불가능**하다. 즉 DEV 절차 6번은 키보드로 수행할 수 없다.
- 더 심각한 부작용: 설정 패널이 열려 있는 상태에서 `ui_up` x3 → `ui_accept` 를 누르면
  패널 뒤의 "새 게임" 이 실행되어 **설정 화면이 열린 채로 게임이 시작된다**(DAY 1 아레나 진입 확인).
  같은 방식으로 "종료" 도 눌린다.
- 세이브 보호는 유지된다(`_on_new_game_pressed` 가 여전히 덮어쓰기 확인을 띄운다).
  따라서 데이터 손실은 없지만 S6 "키보드 전용 조작" 요구를 만족하지 못한다.

**원인**: `scenes/ui/settings.tscn` 루트 Control 이 모달이 아니고 `focus_neighbor_*`
지정이 없어, Godot 의 기하학적 포커스 탐색이 뷰포트 전체에서 후보를 고른다.

**참고**: 인게임(main.tscn)의 설정 패널도 같은 씬이라 같은 구조적 문제를 갖는다.
다만 F7 이 타이틀에 이 패널을 새로 붙이면서 "키보드로 볼륨 조절 가능"을 검수 기준으로
선언했으므로 F7 결함으로 계상한다.
마우스로는 정상 동작한다(효과음 25% 조절 → 라벨 동기화 → 저장 → 재실행 후 복원까지 확인).

### HIGH-2 — 되돌릴 수 없는 확인 창의 본문 대비 1.37:1 (WCAG AA 실패)

**재현**: 세이브가 있는 상태에서 타이틀 → "새 게임" → 확인 창.

**기대**: 본문 대비 4.5:1 이상 (WCAG AA 일반 텍스트).

**실제**: 캡처 프레임(`f7_04_overwrite_confirm.png`)에서 픽셀 실측:

```
dialog panel bg  : #404040
body text        : #33291e
contrast ratio   : 1.37 : 1
```

"저장된 진행 상황이 사라지고 DAY 1부터 다시 시작합니다. 되돌릴 수 없습니다." 라는
**되돌릴 수 없는 동작의 경고문**이 사실상 읽히지 않는다. 창 제목 "새 게임 시작" 도 같다.

**원인**: `theme/jamo_theme.tres` 가 `Label/colors/font_color = Color(0.2, 0.161, 0.118)`
로 어두운 잉크색을 쓰는데, `AcceptDialog` / `Window` 계열 스타일이 테마에 없어
다이얼로그 패널은 Godot 기본 어두운 배경(#404040)으로 그려진다.

**대조**: 타이틀 본문에 대한 DEV 주장치는 실측으로 확인됨.

- "이어하기 사유" 안내 문구: **10.02 : 1** (DEV 주장 ~10:1, 통과)
- 비활성 "이어하기" 라벨: **2.45 : 1** (DEV 주장 ~2.5:1, WCAG 비활성 컨트롤 예외 적용 타당)

즉 DEV 의 대비 검토 자체는 맞지만 **이번에 새로 추가한 ConfirmationDialog 를 측정 범위에서
빠뜨렸다.** 인게임 "저장 데이터 삭제" 확인 창(`%DeleteConfirm`)도 같은 문제를 갖는다(기존 이슈).

### MEDIUM-1 — 아래 화살표가 비활성 "이어하기" 에 멈춘다 (DEV 절차 3번 불일치)

**재현**: 세이브 없는 상태 타이틀 → `ui_down` 1회.

**기대**(DEV 절차 3): "포커스 테두리가 새 게임 → 설정 → 종료 순으로 이동한다.
비활성인 이어하기는 건너뛴다."

**실제**: 포커스 테두리가 비활성 "이어하기" 에 그려진다. 한 번 더 눌러야 설정으로 간다.
Enter 를 눌러도 아무 일도 일어나지 않아 오작동은 없다.

**원인**: `title_screen.gd:refresh()` 가 `disabled` 만 설정하고 `focus_mode` 를 건드리지 않는다.
Godot 4 의 `find_valid_focus_neighbor` 는 disabled 버튼을 후보에서 제외하지 않는다.
헤드리스 테스트 `qa_f7_title.gd` 도 "keyboard reachable" 목록에 ContinueButton 을
포함시키고 있어 이 상태를 잡아내지 못한다(테스트가 `grab_focus()` 를 강제하기 때문).

모든 버튼에 도달은 가능하므로 단독 차단 사유는 아니다.

### MEDIUM-2 — "새로 시작" 이 볼륨 설정까지 지운다

**재현**

1. 타이틀 → 설정 → 효과음 25%, 음악 60% 로 조절 → 닫기.
2. 게임을 진행해 세이브를 만든다.
3. 타이틀 → "새 게임" → "새로 시작".
4. 타이틀 → 설정.

**기대**: 진행 상황만 초기화된다. 확인 창 문구도 진행 상황만 언급한다.

**실제**: 마스터/음악/효과음이 전부 100% 로 돌아온다. 파일 자체가 삭제되기 때문이다.
`_on_overwrite_confirmed()` → `SaveManager.delete_save()` 가 `audio` 키까지 포함한
파일 전체를 지운다. 이후 `main.gd._ready` 의 `load_game()` → `load_audio_settings()` 는
빈 파일을 읽는다. 프로세스가 새로 뜨는 실제 플레이에서는 인메모리 값도 없으므로 기본값 복귀.

DEV 가 `save_settings()` 를 따로 만들어 "진행 없이 볼륨만 저장" 은 지켰지만
반대 방향(진행 삭제 시 볼륨 보존)은 처리되지 않았다.
인게임 설정의 "저장 데이터 삭제" 도 동일하다(기존 경로).

### LOW-1 — 확인 창 "취소" 후 포커스가 사라진다

취소를 누르면 어떤 버튼에도 포커스 테두리가 없다. 화살표를 한 번 더 누르면 복귀하므로
조작 불가는 아니지만, 키보드 사용자는 현재 위치를 잃는다.
`%OverwriteConfirm` 의 `canceled` 를 `focus_default_button()` 에 연결하면 해결된다
(설정 패널의 `closed` 처리와 같은 패턴).

### LOW-2 — `tests/qa_f7_title.gd` 가 실제 세이브를 백업 없이 삭제한다

`_ready()` 첫 줄과 종료 직전에 `SaveManager.delete_save()` 를 호출한다.
개발자가 이 테스트를 로컬에서 돌리면 진행 중인 세이브가 그대로 날아간다.
테스트 시작 시 파일을 옆으로 옮겨 두고 끝나면 되돌리는 편이 안전하다.

## 4. 기타 관찰

- **NotoSansKR 폰트 누락**: 사전 존재 이슈. 그대로 재현되며 F7 판정에 반영하지 않음.
- **에디터 로그의 `Identifier not found: AudioManager`**: 에디터 캐시에 남은 낡은 파스 에러다.
  같은 스크립트가 헤드리스에서 정상 컴파일되고 라이브 실행도 정상이므로 실제 결함 아님.
- **SignalBus 미사용 시그널 경고 12건**: 에디터 GDScript 경고. 사전 존재, F7 무관.
- **엔진 생성 `.uid` 파일**: 이번 검증 실행 중 `scripts/ui/title_screen.gd.uid`,
  `tests/qa_f7_title.gd.uid` 가 새로 생성됐다. DEV 가 보고한 `tests/qa_f6_*.gd.uid` 와
  같은 성격이며 커밋 포함 여부는 총지휘자 판단.
